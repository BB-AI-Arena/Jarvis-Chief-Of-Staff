# Board answers, screenplay consultation and voice delivery

Jarvis has read-only evidence from the current task ledger and saved Results, plus relevant shared-workspace passages. Typed, local and realtime client routes can use `lookup` to read a permitted text file in UTF-8 pages or list the complete text inventory. Full result availability is separate from having every document in every model context. Ordinary greetings do not scan or inject the full archive.

`DirectorBrief` carries the complete assignment, deliverable criteria and actual role/machine capabilities. In particular `run_on_dark` is Linux access, not access to the Mac's Application Support directory. A source edit, a build and a verified installed change are distinct states. CTO provider failures now retain sanitized concrete diagnostics where available in the task result and private `provider-errors.jsonl`; missing historical diagnostics cannot be reconstructed as fact.

Research screenplay reviews use a final JSON judgment (`StoryReview`) bound to the exact screenplay SHA-256, with specific numbered changes and evidence. Progress-only messages and stale judgments trigger bounded delivery recovery, not a Creative rewrite or a disagreement count. Valid corrections go to Creative with the full current script and owner brief; Creative returns a full revision and resolution record. Research reviews the same revision, and Creative confirms the unchanged accepted version or revises it. Up to six completed review rounds are supported; a remaining blocker must be concrete and preserved, never reported as a vague vote count.

For writing-only Story consultation tasks, a configured `story-writer-provider.txt` value of `anthropic` uses the selected Claude Creative model through the existing Anthropic connection; other Creative work retains its configured provider path. This mode avoids repository work for prose. If the connection/configuration is absent, the existing Creative provider remains available. Record actual model/provider use rather than relabeling old outputs. Current owner choices are Creative Opus 5.5 and Research Grok 4.7.

The current original brief and screenplay persist in `film-story.json`. Repeated requests to generate/finish the saved script resume that consultation rather than creating unrelated drafts. Jarvis presents the complete jointly agreed version in Results. Owner approval binds to that hash and automatically queues film production from the approved screenplay; no second confirmation is required. Script-only jobs cannot start rendering simply because their context mentions a film. Production for this consultation requires the valid saved approval/version and matching workflow task.

The local conversation voice is the selected Kokoro voice, passed explicitly from the picker to the native microphone/greeting path. The current British profile is Lewis (`bm_lewis`), English GB, measured delivery; this is an original stock voice, not a cloned actor. A one-time preference update applies the owner's current British selection. Changing Jarvis's picker voice cancels/restarts the active conversation onto the selected local voice. Local synthesis is preloaded at launch to reduce first-response startup. Physical audible output and subjective performance require listening; synthesis/configuration alone does not prove a film-identical sound.
